# UI 走查与优化（2026-11-23）

范围：首页、阅读统计、阅读计划/空余时段（新）、设置/列表/键盘等既有屏幕及其共用组件。设备为 OnePage S3，Lyra 主题、竖屏 480×800 可视区，纯按键操作。

方法：`scripts/device_test.py` 抓取真机截图（`/tmp/ui/run1` = 优化前，`/tmp/ui/run2` = 优化后）+ 主题/页面代码走查；对照 ui-ux-pro-max 的 Accessibility / Interaction / Forms / Navigation 规则（焦点可见、错误就近、空状态、导航可预期）。触控尺寸、动效时长等触摸/Web 规则不适用于本设备，未套用。

## 设计系统现状

- 主题：`src/components/themes/`（Lyra 默认、Base、RoundedRaff）；页面统一经 `GUI` 宏取 `UITheme`，新增代码无硬编码字体/边距。
- 字体层级：UI_12 标题、UI_10 正文、SMALL 辅助；单色 + LightGray/DarkGray 抖动，无彩色可用。
- 列表：`drawList` 统一选中态（Lyra 圆角浅灰、Base 整行反白），值列右对齐并按主题限宽截断。
- 导航：Back 返回、方向键移动、Confirm 选择；每屏底部有按键提示。

## 发现与处理

| 屏幕 | 问题 | 影响 | 处理 |
|---|---|---|---|
| 阅读计划列表 | 空列表时「空余时间」排在「新建计划」前，默认焦点落在次要项 | 首要动作不在第一行，容易误入 | 顺序改为 计划 → 新建计划 → 空余时间；空列表首行即「新建计划」 |
| 阅读计划列表 | 行标题以日期开头，副标题是完整 SD 路径 | 长路径被截断，计划难以按书识别 | 标题=书名（basename），副标题=目标日期 + 每周分钟 |
| 阅读计划列表 | 两个动作行只有一行文字，60px 行高留下半行空白 | 像渲染缺口 | 动作行补一行说明文案（新建计划 / 空余时间） |
| 计划编辑 | 目标书籍显示完整路径；每周页数 0 显示「0 页」 | 截断 / 误解为「目标 0 页」 | 值列=文件名；0 显示「不限」 |
| 计划编辑 | 编辑已有计划与列表共用标题「阅读计划」 | 层级不清 | 已有计划标题改为「编辑计划」 |
| 空余时段 | 新时段默认名与页标题同为「空余时间」；日期用半角逗号连接 | 命名重复，中文观感差 | 默认名「阅读时段」；日期用空格分隔 |
| 首页 | 第 11 个 tile（阅读计划）选中时书签图标与标签仅 4px | 选中态最显眼处视觉相接 | Lyra 图标-标签间距 4→8px（首页栅格全局生效） |

## 保留项（需要更大范围的设计决策）

1. **选中行抖动底纹上的小字**：50% 抖动在长 CJK 小字下会让笔画发虚（截图可见）。修法应是「白底 + 1px 边框」的选中态，会影响全部列表与三套主题，需独立评审与全屏回归。
2. **Base 与 Lyra 的选中语义不一致**：Base 整行反白铺满，Lyra 内缩圆角浅灰。统一需要产品确认。
3. **阅读统计**：汇总值列固定 150px、图例紧凑、月份只有数字；信息密度与竖向留白可再平衡。页面刚通过真机验收，留待专门一版。
4. **首页 11 tile 的最后一行**只剩 2 个 tile，左对齐、右下留空；居中末行要改全局栅格函数。
5. **日期/时间输入**仍走键盘（YYYY-MM-DD、HH:MM）；日历页目前不是选择器，做日期选择器需先抽 picker。
6. **归档计划**与进行中计划同列显示；按「归档不丢数据」保留可见，后续可加「显示已归档」开关。
7. **空余时段的 7 个星期开关**占 7 行；更紧凑的 7 格 chip 行会牺牲按键焦点的可预期性，暂不采用。
