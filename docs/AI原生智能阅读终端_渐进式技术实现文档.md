# AI 原生智能阅读终端  
**渐进式技术实现文档（V1.0）**

**文档版本：** V1.1  
**文档状态：** 工程执行基线 / 可供产品、固件、服务端、UI 与 AI 工程团队直接排期  
**对应产品需求：** 《AI原生智能阅读终端_完整产品需求文档》V1.0  
**产品定位：** 从「电子书阅读器」升级为「个人知识操作系统与终身学习伙伴」

**V1.1 变更摘要：** 补充「AI 侵入双模式」与「章末智者闲聊式引导」（非题库测验）；明确自主模式须用户开启、章末仅邀请不强制。

## 0. 总体策略与边界

### 0.1 必须做（Must）

| 优先级 | 能力 | 原因 |
|--------|------|------|
| P0 | 稳定离线阅读 + 进度/书签/笔记 | 产品立身之本 |
| P0 | 当前段落上下文 AI 问答（带原文定位） | 最小 AI 价值 |
| P0 | 本地待同步队列 + 幂等同步 | 断网可用 |
| P0 | 实体按键 + Push-to-Talk 语音 | 墨水屏交互主路径 |
| P1 | 书籍解析流水线 + 章节/段落稳定 ID | 可信引用基础 |
| P1 | 知识卡片 + 用户确认入库 | 知识沉淀 |
| P2 | 学习目标/复习/间隔重复 | 学习闭环 |
| P2 | 章末智者闲聊式引导（用户开启自主模式后） | 主动服务且不破坏阅读节奏 |
| P3 | 受控 Agent（事件触发 + 分级权限） | 主动服务 |

### 0.2 坚决不做 / 延后（Don’t / Later）

- **设备端绝不跑大模型**（哪怕是 0.5B 量化）。ESP32-S3 只做采集、渲染、缓存、状态机。
- **不做「永远在线的聊天机器人」**。AI 必须有明确上下文范围和权限等级。
- **不做复杂动画、手机式卡片堆叠 UI**。墨水屏以静态、高对比、少刷新为准。
- **不默认保存原始语音**。仅在用户明确开启且可删除时才存。
- **不自动执行 L3/L4 操作**（删数据、外发、购买等）。必须显式确认。
- **不把 AI 生成内容伪装成用户观点或书中原文**。来源分层强制执行。
- **章末自主交互不做题库式测验**（「问题 1/3、请作答、对错评分」）。应采用智者闲聊、引导式对话。
- **未开启自主模式时，章末零打扰**；开启后也只出邀请条，不自动开麦、不自动全屏开聊。
- **V0–V1 阶段不做**完整知识图谱、跨书深度研究工作台、多设备实时协同、章末自主闲聊（闲聊能力放在 V2/V3 与导师模式对齐后落地）。

### 0.3 端云职责硬边界

| 设备端（ESP32-S3） | 服务端 |
|--------------------|--------|
| 墨水屏渲染、翻页、目录、进度 | 书籍解析、分章、段落定位、索引 |
| 本地笔记/书签、待同步队列 | 全文 + 向量检索、RAG、引用回写 |
| 语音采集、状态机、TTS 播放 | ASR / LLM / TTS / Embedding |
| 轻量规则、快捷指令、UI 状态 | 知识卡片、记忆、学习计划、Agent 调度 |
| 网络认证、安全同步 | 多端同步、冲突解决、审计日志 |
| 资源监控、OTA、日志 | 模型路由、限流、成本控制 |

## 0.4 AI 侵入模式与章末智者闲聊（V1.1 补充）

AI 进入阅读体验的方式分为两类，产品与实现上必须区分，不可混成「随时弹窗聊天」。

### 0.4.1 双模式定义

| 模式 | 触发方 | 典型入口 | 默认策略 |
|------|--------|----------|----------|
| **用户调用式** | 用户主动 | 选中文本工具条、AI 键、Push-to-Talk | 始终可用（需网络时提示） |
| **自主侵入式** | 系统事件 + **用户事先授权** | 章节阅读完成、学习计划节点等 | **默认关闭**；仅在设置/导师模式中开启 |

自主模式的产品语义：用户允许 AI 在约定时机**发出邀请**，而不是允许 AI 随时打断或自动开聊。

### 0.4.2 用户调用式（简述）

- 阅读页保持主界面；AI 为临时层（半屏结果或独立页）。
- 选中后高频动作：解释、总结、保存；更多进二级。
- 语音：`空闲 → 录音 → 识别 → 思考 → TTS 播报 → 完成`，全程可取消。
- 关闭后恢复原章节与阅读位置；结果带来源标签，不写入正文排版。

### 0.4.3 自主侵入式 · 章末「智者闲聊」引导（重点）

**场景：** 用户读完一章后，若已开启自主闲聊，系统在章末给出**轻量邀请**；用户同意后进入与「阅读伙伴」的引导式闲聊，围绕本章知识与个人感受展开，而非做题。

**交互流程：**

```text
章节进度 = 完成
    ↓
自主闲聊开关 = 开？
    ↓ 否 → 无任何打断，可直接进入下一章
    ↓ 是
底部邀请条（不自动全屏、不自动语音）
  「本章可以收一收了 · 若愿意，陪你闲聊几句——像散步时聊书」
  [坐下聊会儿]  [先往下读]
    ↓ 坐下聊会儿
闲聊会话（引导式）
  · 伙伴先分享观察/感受（非「问题 1/3」）
  · 用户接话（短句选项或语音自由说或「我再想想」）
  · 伙伴顺着用户的话往生活场景轻带一点，必要时点到书中依据
  · 轻收束：「有这个念头就够了」，不布置作业感
    ↓
[聊完了，继续读] → 进入下一章；可选将用户原话存为笔记（需确认）
```

**闲聊风格原则（实现与 Prompt 约束）：**

1. **先分享，后邀请开口** —— 伙伴先说一段，再留空给用户，而不是连续抛考题。
2. **接话优先于答题** —— 提供的是态度/接话短句，不是标准答案选项；沉默、「再想想」合法。
3. **贴着本章，落到生活** —— 少复述目录，多一个可感的日常场景；需要依据时标注书中定位。
4. **收束要轻** —— 不评分、不强制生成复习题；可提示「若愿意可存一句笔记」。
5. **角色定位** —— 「读完同一章的温和伙伴 / 智者式闲聊」，禁止考官口吻与题库结构。

**禁止行为：**

- 未开启自主模式仍在章末弹邀请或自动进入对话。
- 邀请后自动开麦、自动 TTS 朗读开场白。
- 「问题 1/3、请用自己的话说明、正确率」等测验 UI。
- 对同一章在用户选择「先往下读」后反复纠缠式重弹（可提供「下次提醒」但须克制频率）。

**权限与数据：**

- 触发与邀请展示：等同 Agent **L0**（建议级，可自动展示邀请条）。
- 进入会话与生成内容：L0/L1；写入知识库/复习卡片须用户确认。
- 会话可中断、可结束；结束不得阻塞进入下一章。

**建议落地版本：** V2 末或 V3（需稳定章节完成事件 + 对话上下文）；V1 仅预留开关与事件钩子，不做完整闲聊。

**UI 参考演示：** `eink_ai_sage_chat_demo.html`（墨水屏风格：反色、少动画、全刷模拟、接话式选项）。

### 0.4.4 与阅读模式的关系

| 阅读模式 | 调用式 AI | 章末智者闲聊 |
|----------|-----------|--------------|
| 自由阅读 | 随时可调 | 默认不开启自主 |
| 辅助阅读 | 随时可调 | 可选开启 |
| 导师阅读 | 随时可调 | **建议默认开启**（仍可关） |
| 研究阅读 | 随时可调 | 可选；风格更偏依据与比较，仍避免题库感 |

## 1. 推荐技术栈

### 1.1 设备端（Firmware）

| 组件 | 推荐 | 说明 |
|------|------|------|
| 框架 | **ESP-IDF 5.3+ / 5.4**（优先）或 PlatformIO + Arduino-ESP32 | 长期建议 ESP-IDF，便于 PSRAM、分区、电源精细控制 |
| 板级 | 自定义 `board` 组件，明确 N16R8 + 实际引脚 | 与任何 C61 目标彻底分离 |
| 显示 | 根据实际面板选择：GxEPD2 / 厂商驱动 / Free-Ink SDK 风格抽象 | 必须支持 partial / full refresh 策略 |
| 存储 | FatFS（SD）+ LittleFS（内部） | 书籍在 SD，设置/进度可内部 |
| 音频 | I2S + 实际 Codec（ES8311 等） | 录音环形缓冲，避免整段进 RAM |
| 输入 | GPIO 按键 + 消抖 + 长按 | 加速度计手势默认关闭 |
| 网络 | HTTPS + WebSocket（可选） | 默认不常驻连接 |
| OTA | ESP-IDF OTA + 双分区 | 升级失败可回退 |

**关键编译配置提示（N16R8）：**

- Flash 16 MB、PSRAM OPI
- 若用 Arduino：`board_build.arduino.memory_type = qio_opi`
- 分区表使用 16 MB 友好方案（含 OTA + 文件系统）
- 严格监控 PSRAM / 堆峰值，阅读页不得依赖大块连续堆

### 1.2 服务端

| 组件 | 推荐 | 备选 |
|------|------|------|
| API | FastAPI / Go（Gin） | NestJS |
| 数据库 | PostgreSQL | SQLite（单机试点） |
| 对象存储 | MinIO / S3 | 本地磁盘（开发） |
| 向量 | Qdrant / pgvector / LanceDB | Chroma（小规模） |
| 全文 | Tantivy / Elasticsearch / Meilisearch | PostgreSQL FTS |
| 任务队列 | Redis + RQ / Celery / Bull | 简单时可进程内 |
| 模型接入 | 统一 Adapter（OpenAI 兼容 + 本地 Ollama） | 按任务路由 |
| 认证 | 设备证书 / JWT + 设备绑定 | — |

### 1.3 Web 工作台

- 前端：React / Vue + 简洁后台布局（不要做成手机 App 风格）
- 功能：书籍上传、笔记查看、知识卡片确认、设备状态、同步日志、隐私设置

### 1.4 AI / RAG 核心

- 切分：章节 → 段落 → 语义片段，**稳定 `passage_id`**
- 检索：BM25 + 向量混合 + 可选 Rerank
- 回答：强制「来源标签 + 定位」输出格式
- 记忆：仅用户确认的长期记忆进入正式库

## 3. 渐进式版本与实现步骤

### V0：硬件与现有代码适配（2–4 周，阻塞项）

**目标：** 真实硬件上「能稳定亮屏、翻页、存进度」，与任何错误板级配置彻底脱钩。

**步骤：**

1. 盘点原理图/实物：墨水屏控制器与分辨率、按键 GPIO、音频 Codec、IMU、RTC、SD、电池。
2. 新建独立 `board_s3_n16r8` 目标，禁止复用 C61 宏。
3. 验证：PSRAM 可用、Flash 分区、SD 挂载、按键消抖、全刷/局刷、休眠电流粗测。
4. 最小阅读：打开 TXT 或简单 EPUB → 翻页 → 进度写入 → 重启恢复。
5. 输出《硬件能力清单 + 已知问题清单》。

**验收：** 可重复编译烧录；断网可读最近书；无崩溃；无错误外设初始化。

**不做：** 任何 AI、任何 Web 复杂功能、任何 Agent。

---

### V1：可靠 AI 阅读器（MVP，6–10 周）

**目标：** 用户可导入一本书 → 离线阅读 → 联网对当前段落提问 → 回答带定位 → 笔记保存并同步。

**设备端：**

- 书籍管理（EPUB2/3 + TXT 优先）、书架、目录、书签、划线、个人批注
- 阅读引擎适配层（可基于现有/参考项目二次开发）
- AI 交互 UI：选中文本 → 解释/总结/保存；Push-to-Talk 状态机
- 本地待同步队列（笔记、进度、AI 结果摘要）
- 基础日志与错误码

**服务端：**

- `POST /v1/books`、解析状态查询
- 简单切分（章节 + 段落）+ 全文索引（可先不做向量）
- `POST /v1/reader/query`：携带 `book_id + passage_ids + selected_text`
- 回答格式强制：`[书中原文] / [外部补充] / [推断]` + 定位
- 同步 push/pull、设备认证

**Web：** 书籍上传、设备在线状态、笔记列表、基础隐私开关。

**验收（对齐 PRD 13.1 / 13.2 / 附录 A）：**

- 断网可读、可记笔记；恢复网络后笔记只同步一次
- 段落问答必须引用当前段落；超出内容明确标注
- 用户取消请求后不播放过期 TTS

**明确不做：** 跨书检索、知识图谱、学习计划、主动 Agent、复杂 UI。

---

### V2：书籍理解与个人知识库（8–12 周）

**目标：** 多书可索引；知识卡片可确认入库；检索带来源。

**重点实现：**

- 完整解析流水线：校验 → 元数据 → 目录 → 正文 → 段落 ID → 索引
- 章节摘要 / 全书导读（服务端生成，设备只展示）
- 知识卡片 CRUD + 用户确认状态 + 来源定位
- 混合检索（BM25 + 向量）+ 「只检索已确认知识」开关
- Web 知识工作台

**验收：** 多书主题检索带来源；候选卡片需确认才进入正式库；删书时用户可选择保留个人笔记。

**不做：** 完整学习路径、主动 Agent 执行外部动作。

---

### V3：学习与记忆系统（6–10 周）

- 学习目标 / 计划 / 复习（FSRS 或 SM-2，可替换）
- 理解检测以启发式为主，**非伪装精确测评**
- **章末智者闲聊式引导**（见 §0.4）：用户开启自主模式后，章末邀请 → 引导式闲聊 → 可结束进入下一章
- 用户记忆可查看、编辑、删除、导出
- 复习提醒与章末邀请均不强制打断阅读

**验收：** 设定主题目标 → 系统安排阅读与复习 → 进展可见；记忆可彻底删除。  
**章末闲聊验收：** 关闭自主模式时章末无邀请；开启后仅底部邀请且可「先往下读」；会话为接话/闲聊风格而非题号测验；结束可进入下一章。

---

### V4：受控 Agent（8+ 周）

- 事件总线 + 任务队列 + 权限等级 L0–L4
- 任务生命周期：触发 → 计划 → 展示 → 批准 → 执行 → 审计
- 仅自动执行 L0/L1；L2 可撤销；L3 每次确认

**验收：** 权限不足只建议不执行；拒绝后不再自动重试同一动作；失败可恢复且无副作用重复。

---

### V5：生态与高级能力（后续）

多设备、OCR、外部工具、私有化部署、可插拔模型等——在 V1–V4 稳定后再开。

## 4. 关键数据与接口（实现时优先固化）

### 4.1 最小实体集

- `Book`：书籍元数据、文件哈希、格式、解析状态
- `BookChapter`：章节层级、标题、顺序和定位
- `Passage`：原文片段、**稳定定位 ID**、索引状态
- `ReadingProgress`：用户、书籍、章节、位置、更新时间
- `Annotation`：原文引用、用户批注、类型、定位
- `Conversation` / `Message`：对话及上下文引用
- `KnowledgeCard`：知识内容、来源、类型、确认状态
- `SyncOperation`：变更 ID、版本、幂等键和同步状态
- `Device`：设备身份、固件版本、能力清单和最后在线时间

所有实体需包含创建/更新时间、版本字段和必要的软删除/恢复策略。

### 4.2 统一 AI 请求上下文

每次请求应显式传递：

- `user_id`、`device_id`、`request_id`
- `intent`：explain / summarize / compare / apply / quiz / **chapter_chat**（章末智者闲聊）等
- `context_scope`：current_book / selected_books / knowledge_base / user_selected
- `book_id`、`chapter_id`、`passage_ids`（适用时）
- `selected_text` 和必要的上下文片段
- `response_style`、语言和输出长度（`chapter_chat` 时应约束为伙伴口吻、禁止题库结构）
- `autonomous_opt_in`：是否已开启自主闲聊（服务端二次校验）
- 用户授权的工具列表
- `privacy_policy` 与数据保留选项

**不要把完整书籍或全部用户记忆无差别地塞入每次请求。**  
**章末闲聊**请求应携带本章摘要或关键段落引用范围，以及最近用户接话，而非整书全文。

### 4.3 同步原则

- 字段级版本或明确冲突策略
- 禁止「最后写入覆盖一切」导致笔记丢失
- 提供同步状态、失败原因和手动重试

### 4.4 核心 API（逻辑级，正式开发前需定义 Schema）

## 6. 风险与工程约束（执行时天天看）

1. **先保护阅读链路** —— AI 功能崩溃不得影响翻页与笔记。
2. **先确认真实硬件** —— 引脚、控制器、音频、PSRAM 必须实测。
3. **先做稳定定位 ID** —— 没有段落 ID 就没有可信引用。
4. **先做最小闭环** —— 导入 → 读 → 问 → 引用 → 存 → 同步 → 检索。
5. **所有 AI 输出有来源边界**；所有主动行为有权限边界。
6. **数据可导出**（Markdown/JSON），避免锁定。
7. **接口与数据结构版本化**；每个版本有书面验收用例。

### 主要风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 现有项目目标板与实际 S3 硬件不一致 | 无法编译或外设异常 | 先完成板级适配审查，独立维护 target |
| 书籍解析不完整 | AI 引用和摘要不可信 | 解析质量标记、定位校验、失败降级 |
| AI 幻觉 | 错误知识沉淀 | RAG 引用、来源分层、用户确认 |
| 服务端不可用 | AI 功能中断 | 离线阅读、本地队列、重试机制 |
| 长期记忆失控 | 隐私和信任问题 | 用户可查看、编辑、关闭和删除 |
| Agent 越权 | 数据或外部操作风险 | 最小权限、分级授权、审计日志 |
| 墨水屏刷新限制 | 复杂交互体验差 | 静态优先、局部刷新、页面层级简化 |
| ESP32-S3 资源有限 | 内存不足、响应慢 | 设备端轻量化、分块处理、云端推理 |
| 多端数据冲突 | 笔记丢失 | 版本控制、幂等同步、冲突显式处理 |
| AI 服务成本上升 | 长期运营成本高 | 模型路由、缓存、限额和可配置服务 |

## 10. 开发团队执行约束（摘要）

1. 先保护现有可用阅读能力。AI 功能不得破坏基础阅读链路。
2. 先确认真实硬件。用户设备是 ESP32-S3 N16R8；仓库中出现的 C61 target 必须与实际板级配置区分。
3. 先做端云边界。设备负责交互和离线可靠性，服务端负责重推理和知识处理。
4. 先做数据模型和定位。没有稳定的书籍、章节、段落 ID，就无法建立可信引用和知识回溯。
5. 先做最小闭环。导入一本书 → 阅读 → 选段提问 → 引用回答 → 保存笔记 → 同步 → 检索。
6. 所有 AI 输出都要有来源边界。不把推断伪装成原文，不把 AI 内容伪装成用户观点。
7. 所有主动行为都有权限边界。先建议，再确认，再执行；重要动作有日志和撤销能力。
8. 数据开放可迁移。用户笔记、知识卡片、学习记录支持导出。
9. 接口版本化。设备固件、服务端 API、数据结构和模型适配器分别演进。
10. 每个版本都有验收用例。不以「页面做出来了」作为功能完成标准。
