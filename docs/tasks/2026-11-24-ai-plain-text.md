# AI 回复纯文本化（2026-11-24）

对应 v4.0 §3.4 新 bug B、AI-01 子项 ③（Markdown→纯文本轻渲染）。状态：**完成**。

## 问题

relay 原样返回 LLM 的 Markdown，最终回复直接上屏：`**8:00**`、`` `snprintf` ``、`##` 标题、代码围栏都会以裸符号出现在 1-bit 固定字号界面上；聊天记录与语音书签条目也会存下这些符号。

## 做法

新增 `lib/PlainText/PlainText.{h,cpp}`，`stripMarkdown(char*, len)` 就地压缩、零分配：

- 去掉成对/成串的 `**` `__` `~~` `***`，以及 `*斜体*` / `_em_`（仅当两侧是词边界）；
- 去掉反引号与代码围栏行（``` / ~~~ 及 ```` ```cpp ```` 这类 info string），保留块内文本；
- 去掉行首 `#`~`######` 标题标记；
- 合并连续空行（最多留一行），去掉行尾空白与 CR；
- 保护 `2 * 3`、`5*3`、`file_name` 这类正文符号；UTF-8 字节原样透传。

接入点在 `VoiceRelay::ChatClient::ask()` 解析成功之后、日志之前：所有走该客户端的消费者（AI 书童回答、词典/单词卡、语音助手、书签记录、朗读 TTS）一次生效。缓冲区本来就是调用方提供的 NUL 终止文本，就地改写不新增内存。

## 验证

- 主机新增 `PlainTextTest` 9 例（强调/标题/围栏/空行/UTF-8/幂等/CRLF/链接/未终止），全套 **397 passed**。
- `pio run -e onepage_s3` 通过。
- 真机未专门验证：需要 LLM 恰好返回带 Markdown 的回复；串口在触发时会打印 `markdown stripped: X -> Y bytes`，可据此确认。词典/书童的普通回复路径不受影响（无标记时 `X == Y`，不打印）。

## 后续

- 完整 Markdown 子集（列表、表格、链接）与引用片段渲染属于 AI-01 的剩余工作，需和 Bridge 一起做；本模块只处理“符号噪音”，不改变行文。
- `/api/v1/reader/query` 的引用片段走 `ReaderQuery` 解析，不经过本模块；若服务端开始返回 Markdown，再在该层接入。
